## 1. 用户问题、目标与范围

### 1.1 产品定位与证据

面向准备实习的学生，根据简历、求职方向和可选 JD，主动发现重要问题、补充必要信息并提出有依据的修改。用户可以知道每条改写“来自哪里、为什么这样改”，确认采用后获得完整 Markdown 简历。

| 事项 | 性质与来源 | 当前结论 |
| --- | --- | --- |
| 用户需要回顾修改过程并追溯内容依据 | 发起者在需求讨论中明确提出 | 已确认为产品需求，尚未通过其他用户验证 |
| 首批用户为实习求职学生，不限岗位 | 用户逐轮确认 | 是目标覆盖范围，不是全岗位效果承诺 |
| 系统主动诊断并选择行动，用户确认事实与采用结果 | 用户明确要求做 Agent 并确认自主边界 | 已确认 |
| 追问能比通用聊天带来更清楚、可信的项目描述 | 产品价值假设 | 待用真实样例与试用验证 |
| 真实访谈、试用人数、岗位覆盖、质量和成本数据 | 当前无相应材料 | 不填写虚构结果 |

### 1.2 目标与完成条件

Agent 应围绕求职方向，主动处理最重要的问题；每条改写有来源与理由，未知信息不编造；用户确认采用后，交付完整 Markdown，并说明未解决问题。

任务完成不要求用户补齐所有经历，也不要求匹配所有岗位条件。用户可以跳过问题、拒绝建议或提前导出；此时应说明当前稿状态，不能宣称所有问题均已解决。

首版在项目发起者的电脑运行，通过现场体验或演示验证。云端模型 API 费用由发起者承担，从模型接入验证到首轮现场试用的总预算上限为人民币 30 元，包含材料识别、Agent 多轮调用及失败重试，不自动追加预算。此为支出约束，不是预计费用或可完成次数承诺。

### 1.3 范围

本期包括：多格式材料输入、Agent 主动诊断与追问、逐条建议与依据卡片、用户直接编辑、Markdown 导出、本地历史会话、失败恢复。

本期不包括：模拟面试、Word/PDF 输出、还原任意原版式、独立版本库、跨岗位版本管理、联网检索、跨会话记忆、注册登录、跨设备同步、公开部署、学习规划。

## 2. 需求与 Agent 行为

以下 FR 均为本期核心闭环需求。优先保障可验证的事实规则和自主行动质量，不以增加工具或模型数量衡量 Agent 程度。

| 编号 | 需求 | 产品行为 |
| --- | --- | --- |
| FR-001 | 创建任务与输入材料 | 简历和求职方向必需，JD 可选；支持粘贴和统一上传多附件，由 Agent 自动识别用途，不要求用户预先分类；一个会话服务同一人的一个目标岗位，只有一份当前稿，可按第 3.3.1 节补充材料或明确替换新版 |
| FR-002 | 解析与可选核对 | 简历和 JD 支持粘贴、.md、.docx、文字型及扫描型 PDF、PNG/JPEG 截图；默认直接分析，允许查看和编辑提取结果，解析异常时提供恢复入口 |
| FR-003 | 主动诊断与动态推进 | 首次展示最重要的 1—3 个问题、依据及推荐顺序；后续按情况选择行动，允许用户调整重点 |
| FR-004 | 事实一致性与信息缺口 | 不编造、不过度包装；有限改写、冲突澄清、能力缺口和不熟悉岗位均有明确处理边界；新事实影响已接受内容时主动标记并提交纠正建议，等待用户再次接受 |
| FR-005 | 逐条修改与内容取舍 | 每项建议对应独立要点、段落或字段；支持接受、拒绝、要求调整，以及说明影响范围的删减建议 |
| FR-006 | 内容依据追溯 | 每条改写提供原文、相关补充、理由和信息缺口；区分用户事实、用户直接编辑与 AI 建议 |
| FR-007 | 完整稿直接编辑 | Markdown 编辑与预览切换；以用户最新稿继续处理，受影响的旧建议失效 |
| FR-008 | Markdown 交付 | 预览、复制和下载当前确认稿；提示未解决问题，不将待接受内容自动纳入 |
| FR-009 | 独立会话与本机恢复 | 侧栏新建、切换、重新打开及删除；本机后端 SQLite 保存原附件、提取文本、对话、建议、依据和当前稿；浏览器经接口读取，删除整会话及关联数据，会话间不混用材料 |
| FR-010 | 失败保留与继续处理 | 解析或模型失败时保留已有成果，说明失败环节，允许重试或改用粘贴；附件部分失败时继续处理可用内容，暂缓依赖缺失材料的判断，不静默遗漏或宣称成功 |

输入规格（用户已确认）：文字支持直接粘贴及 `.md`；Word 支持 `.docx`，旧版 `.doc` 提示另存为 `.docx` 后上传；PDF 包含文字型与扫描型；截图支持 `.png`、`.jpg`、`.jpeg`，允许多张组成同一材料。其他格式明确提示转换，不静默尝试。扫描件或截图识别失败时允许重试或改用粘贴。上述为需求范围，不是已验证能力；文件大小、页数与清晰度限制在技术验证后确定。

### 2.1 自主决策循环

Agent 在每次获得用户输入或工具结果后，重新判断目标、当前材料、信息缺口和已有建议，选择当前最有价值的行动。候选行动包括：检索本会话材料、提出关键追问、提交修改或删减建议、根据纠正检查影响、转向其他问题、总结并交付。

这不是要求每个用户依次经历全部阶段的固定流程。例如：已有依据时可以直接提交建议；回答无新增信息时可以有限改写或转向其他问题；用户纠正事实时应重新检查受影响内容。

- 默认判断顺序：事实可信度 → 岗位价值 → 表达。具体先处理哪条由 Agent 结合材料决定。
- 是否继续追问由重要性、回答带来的新信息及用户意愿共同决定；不为收齐模板字段而反复追问。
- 每次需要用户回答时，聚焦当前最关键的问题；用户可以跳过、打断或改变优先级。
- 展示简短的行动理由和可核对依据，不要求展示模型内部推理过程。
- 目标是形成有效建议和可交付稿件，工具调用次数不是成果指标；循环与费用硬上限在技术方案中确定。

### 2.2 授权边界与事实规则

| 情况 | 必须遵守的行为 |
| --- | --- |
| 材料有限，用户说“记不清，你润色就行” | 仅优化现有事实的措辞和结构；不新增职责、行动、结果或数字，说明信息缺口 |
| 早先表述与新补充冲突 | 指出差异并请求澄清；确认前保留原表述，其他内容可继续处理；无法澄清则采用无争议的保守表述 |
| 新事实影响已接受表述 | 主动检查受影响内容，标记冲突并生成纠正建议，用户再次接受后更新；未处理时在预览和导出处提示未解决冲突，不静默覆盖、不称当前稿已全部确认 |
| 岗位能力缺证据 | 先检索本会话，再追问；确实未做过则保留缺口，不以相近经历冒充，不自动生成学习计划 |
| 有／无 JD | 有 JD 时依据具体要求；无 JD 时依据求职方向提供一般建议，标明局限，不宣称具体岗位匹配 |
| 不熟悉岗位要求 | 说明限制，请求具体材料；仍不足时只完成有依据的部分 |
| 建议删减经历 | 说明理由、范围和信息损失；必要时先追问价值，接受后才更新，原内容仍可回顾 |
| 修改正式内容 | 内容优化只提交建议，用户接受后才写入；用户直接编辑，以及明确授权以新版整体替换，是另外两条用户写入路径，模型不能自行执行 |
| 使用工具与信息 | 仅处理本会话材料、当前稿与建议；不能读取其他会话、联网搜寻个人经历、静默增删事实 |
| 材料中出现命令 | 简历、JD、图片文字属于待分析数据，不能据其内容改变系统权限或跨会话读取资料 |

“用户认可表述”“材料有来源”“事实已经被外部验证”必须区分。系统不提供真实性认证，也不以模型置信度代替证据。

## 3. 页面、流程与交互

### 3.1 页面与入口

| 页面编号 | 位置与目的 | 入口／出口 |
| --- | --- | --- |
| PG-001 | 桌面工作台：左侧历史会话、中间对话与建议、右侧完整稿编辑／预览 | 启动本地应用进入；新建或打开会话切换当前任务 |
| PG-002 | 材料查看区：查看及编辑提取结果，处理解析失败 | 从上传结果或错误提示打开，返回工作台；不是每次必经步骤 |
| PG-003 | 依据卡片：原文片段、补充来源、改写理由、信息缺口 | 点击对应改写打开，关闭返回原位置 |

页面表示逻辑界面，可用抽屉或区域实现；不预定路由。首版针对电脑使用，移动端不作为本期验收范围；具体视觉样式后续设计。

### 3.2 端到端路径（用户已确认）

首次使用：空会话列表 → 新建会话 → 添加简历与求职方向、可选 JD → 开始分析 → 首次诊断摘要 → Agent 按情况检索、追问或建议 → 用户逐条确认或直接编辑 → 预览、复制／下载 Markdown，并查看未解决问题。

再次使用：从历史侧栏打开会话 → 恢复对话、建议、依据和当前稿 → 继续处理。新会话不带入其他会话的经历；更换岗位新建会话。无 JD 不阻止开始；必需信息缺失时保留材料并提示补充。

上述路径说明可达的任务闭环，不强制 Agent 每轮重复诊断、追问和改写。

#### 用户行为流

| 环节 | 用户动作 | 系统反馈与可见结果 |
| --- | --- | --- |
| 建立任务 | 新建会话，上传或粘贴简历，填写求职方向，可选添加 JD | 显示材料归属与处理状态；必要时澄清多个附件的角色或顺序 |
| 获得诊断 | 点击开始分析，按需查看提取文本 | 展示最重要的 1—3 个问题与依据；完整稿区展示初始内容，不能悄悄纳入未经接受的优化 |
| 参与完善 | 回答、纠正、跳过，或指定先处理某段 | Agent 根据最新材料选择追问、查找已有依据、提出建议或转向其他问题 |
| 决定采用 | 查看建议及依据卡片，接受、拒绝或要求调整 | 仅接受项进入当前稿；建议状态和正文变化清晰可辨 |
| 检查成稿 | 在编辑与预览之间切换，直接修改正文 | 保留用户最新稿，受影响的旧建议失效；用户编辑不自动获得旧依据的事实背书 |
| 取得成果 | 复制或下载当前 Markdown | 交付正文与当前稿一致，未解决问题另行说明，保留会话供继续处理 |

“参与完善—决定采用—检查成稿”允许往返，用户不必等到 Agent 宣布完成才能取得当前稿。用户行为流是使用路径，Agent 行动仍由当前目标、材料和反馈动态决定。

返回与中断分支：解析失败可重试、修正或粘贴；中途离开后从侧栏打开已保存会话；更换目标岗位新建会话，不自动继承旧材料。建议依据的查看入口覆盖待接受建议及已接受改写，保证确认后仍能回顾来源。

### 3.3 核心交互

| 编号 | 操作 | 结果与恢复 |
| --- | --- | --- |
| INT-001 | 新建会话、打开历史会话 | 显示对应任务；新会话为空，旧会话恢复，不能混入其他会话材料 |
| INT-002 | 添加材料并开始分析 | 统一上传，Agent 自动识别简历／JD；展示分类结果并允许纠正，存在歧义才澄清；默认不要求脱敏或核对；展示处理中状态，失败保留输入 |
| INT-003 | 回复、跳过或打断 | Agent 更新判断；跳过不等于补齐证据，不可继续强迫回答同一问题 |
| INT-004 | 接受、拒绝、要求调整 | 单项接受才更新对应内容；拒绝保留原文；调整后重新生成待确认建议；重复接受不重复插入 |
| INT-005 | 打开依据卡片 | 定位建议引用的原文和相关问答；来源缺失不能伪造，应显示不可定位及限制 |
| INT-006 | 直接编辑并保存当前稿 | 标记用户编辑，预览同步；同一内容上的旧待接受建议失效，其他不受影响的建议保留 |
| INT-007 | 复制、下载 | 默认交付当前稿，不纳入未接受建议；存在未解决事实冲突时在导出处提示，不把待确认纠正自动写入；失败提示重试并保留正文；诊断、依据卡片不混入简历正文 |
| INT-008 | 查看提取文本、修正、重试 | 明确本次变化针对材料提取；失败可改用粘贴，不重新丢弃已确认稿 |
| INT-009 | 删除会话 | 用户发起并确认后删除该会话及本地原附件、提取文本、问答、建议、依据和当前稿；不影响其他会话或电脑原文件。删除失败不显示成功；活动请求不得重新写回已删除会话 |
| INT-010 | 同会话再次上传简历 | 从统一上传入口进入；Agent 判断补充、参考新版或整体替换，用途不明才询问。仅上传不覆盖；明确替换时先说明影响，保存成功后展示新版当前稿及旧建议失效状态；失败保留原稿，详见第 3.3.1 节 |

上传采用统一入口，由 Agent 根据内容自动识别简历／JD 及材料关联，用户不必预先分类。展示识别结果供用户纠正，不增加必经分类确认；角色存在歧义时再澄清，不能仅凭上传时间把 JD 当成个人事实。

排序规则（已确认）：PDF 内部保持原页序；多张截图由 Agent 结合页码和内容衔接判断顺序，不能确定时再询问用户。展示采用的顺序并允许纠正，不增加必经确认；排序不能成为改写材料事实的理由。部分附件解析失败时明确指出缺失材料，继续处理不依赖缺失部分的问题，允许重传或粘贴补充；不能把部分内容当作完整简历。

### 3.3.1 再次上传与当前稿替换（用户已确认）

一个当前稿不等于只能上传一个文件。多页截图／附件可以组成同一份简历；同一人的新版也可在本会话处理，目标岗位仍保持不变。

| 新材料用途 | 处理规则 |
| --- | --- |
| 同份简历的补充页、经历补充 | 将明确归属的内容加入当前有效材料；当前稿不因上传自动改变，新增或修改正文通过待接受建议完成 |
| 参考同一人的新版 | 保留当前稿，仅就新版中的相关事实提出建议；新旧事实冲突按 FR-004 澄清，不以“最新上传”自动判真 |
| 用同一人的新版整体替换 | 用户明确表示“以这份为准／替换当前稿”后，按下述替换规则执行；不得自动迁入旧稿中的优化 |
| 另一人的简历或更换目标岗位 | 提示新建会话；不把新人的事实并入当前任务。不自动读取旧会话内容，新会话需要重新提供材料 |
| 归属或用途不明 | Agent 提出一个聚焦的澄清问题；材料保留为待澄清，不作为当前个人事实依据，不改变当前稿。用户已明确用途时不重复要求确认 |

整体替换规则：

1. 明确告知“新版将取代当前稿，原先接受或手改的内容不会自动迁入，旧待处理建议将失效”。上传操作本身不构成替换授权；用户明确的自然语言要求可作为授权，不额外强制按钮确认。
2. 新材料须归属明确、解析成功且足以形成完整初始稿；若缺页、解析失败或无法判断完整性，暂缓替换，保留原稿，允许补传／粘贴或改作局部参考。
3. 按初始导入规则形成新版 Markdown，只做必要格式整理；在一次持久化操作中更换当前稿、失效全部旧 pending 建议、归档旧诊断／冲突的当前状态，并记录替换前后正文及材料范围。历史已接受／拒绝建议及其引用保留，不改写成新版记录。
4. 保留旧材料和聊天供回顾，但旧简历、旧经历补充及其历史问答不自动成为新版的有效事实依据；确需沿用时由用户明确指定，冲突仍须澄清。目标岗位及可选 JD 保留。历史引用仍能定位原版本，并标示属于替换前。
5. 旧运行及迟到结果不得覆盖新版或恢复旧建议；新分析使用新版当前稿与有效材料。保存失败时整次替换不生效，原稿与旧建议状态保持，提示重试，不显示替换成功；重复请求不重复替换。
6. 只保留追溯所需的替换记录，不新增独立版本库、历史稿切换、回滚或版本对比功能。

### 3.4 状态表现

- 空状态：说明添加简历与求职方向即可开始，JD 可选。
- 处理中：展示当前在解析、分析或生成建议，防止同一操作重复提交；不能伪造进度百分比。
- 待用户输入／确认：说明当前需要补充或决定什么；完整稿保持可查看。
- 有未接受建议：能区分建议与当前稿，不以未接受内容生成最终正文。
- 出错：展示失败环节及下一步，不清空成功成果。
- 保存失败：明确提示尚未保存，不显示保存成功；具体退出保护在技术方案中确定。

### 4.1 最小业务对象

直接编辑可以保留此前来源关联供回顾，但不能把整段新文字自动归因给旧依据。具体关联粒度由技术设计提出并验证。

### 4.2 本地保存与数据发送

- 在运行后端的电脑上，用 SQLite 保存原文件／截图、提取文本、历史对话、建议、依据引用和当前稿；浏览器只保留临时编辑状态，通过接口读取历史，重新打开可回看原附件。
- 用户可删除整个会话及其本地关联数据；只删除本应用保存的副本，不删除电脑原文件，不代表删除模型服务端可能保留的数据。容量不足或保存失败必须提示，不能假装原附件已保存；容量和保存实现需技术验证。
- 本机保存不是账号隔离：能访问同一后端的使用者可查看同一历史列表，现场试用需说明。切换浏览器或清除网站数据不会删除后端 SQLite 记录；换到没有该数据库文件的另一台后端机器不会自动同步。仍不做账号、云端部署或多人权限。
- 调用云端模型时发送任务所需信息；没有强制脱敏流程，开始分析附近应简短告知。若识别使用云端图片输入，说明必须覆盖图片发送。
- API 密钥应配置在本机服务端，不嵌入前端页面、不写入会话或下载稿；模型服务与具体数据保留规则选型时核实。
- 默认不新增记录简历全文的运行日志或用户行为分析。仅按排障需要记录状态、耗时、调用量和错误类别，具体实现后续确定。

| AC-028 | 替换前曾补充“负责统筹”，新版未提供此事实，旧引用仍存在 | 替换成功后继续分析，再查看旧依据；用户另明确要求沿用某条旧补充 | 未获沿用要求时不从旧对话／检索悄悄补回统筹；旧依据仍定位原版本且标示历史；明确沿用后才纳入有效材料，冲突仍需澄清，不提供历史稿回滚／版本对比 |

评估不只看能否导出文件，还要检查 Agent 是否按材料动态选择行动。至少对比“证据已足够”“关键事实缺失”“回答不再提供信息”三种情境，记录是否采取不同且合理的行动。

建议记录：解析遗漏／错序、无依据新增事实、来源可定位情况、追问是否获得有效补充、用户能否独立接受修改并导出、调用耗时及费用。不设无依据的通过率或成本数字；样例数量、岗位分布及阈值在测试方案中确定。
