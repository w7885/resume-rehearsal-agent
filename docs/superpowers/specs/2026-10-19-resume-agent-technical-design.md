# 简历修改 Agent｜技术方案与 Agent 行为设计

版本：v0.4 · 更新：2026-10-20 · 状态：按用户决定将业务后端与 Agent 统一改为 Python；实现与模型效果未验证

需求基线：[PRD v0.4](2026-10-19-resume-agent-design.md)。本次同步第 3.3.1 节与 AC-024—AC-028：同会话一个当前稿，允许补充、参考新版或经用户明确授权整体替换。下述字段／接口为待实现设计，不代表已安装依赖、账户已验证或模型效果达标。本轮未调用付费 API。

## 1. 已确认路线与技术选择

已确认：本机运行；业务记录改由本机后端 SQLite 保存，不再采用 IndexedDB；使用 DeepSeek；文本文件先本地提取，截图／扫描页按需发送视觉模型；单模型先验证；本轮总预算 30 元，包含接入验证、识别、Agent 调用及重试。数据属于运行后端的电脑，不是每个浏览器各存一份。

### 1.1 方案取舍

| 方案 | 取舍 | 本文建议 |
| --- | --- | --- |
| 单个 Agent，直接通过 SDK 调用模型和工具 | 循环、状态与权限清楚，便于逐步理解；重试和恢复需要自行实现 | 首版采用 |
| 单个 Agent，使用现成 Agent 框架 | 可复用编排能力，但增加框架概念和版本适配 | 出现明确需求再引入 |
| 多个专职 Agent 协作 | 增加交接、状态同步、费用和排障复杂度 | 本期不采用 |

技术路线（2026-10-20 用户最新决定）：前端保留 TypeScript + React + Vite；整个业务后端与 Agent 统一使用 Python，在同一个后端进程内协作，不再保留 Node／Express 业务后端或额外拆出 Python Agent 服务。Node/npm 仍用于前端开发和构建。

后端框架建议采用 FastAPI，以 Uvicorn 单 worker 运行；共享 Python 数据模型校验请求、工具与事件，前端使用对应 TypeScript 类型，经 JSON／HTTP 通信，不再将“全栈共享 TypeScript 类型”作为方案。[FastAPI 官方说明](https://fastapi.tiangolo.com/)、[手动运行服务](https://fastapi.tiangolo.com/deployment/manually/)。Python 语言已由用户确定，框架及具体依赖是本次修订的实施建议，学习／工程阶段需核对，不声称已获 B/C 确认或已验证可运行。

SQLite 使用 Python 标准库 sqlite3，封装独立 Repository 数据访问层，采用参数化 SQL，不新增 ORM。只读检查已确认本机 Python 3.13.15 可导入 sqlite3（SQLite 3.50.4）；未创建项目数据库或验证业务读写。[Python SQLite 文档](https://docs.python.org/3.13/library/sqlite3.html)

同一数据库连接不在多个并发线程随意共享；Repository 按明确连接生命周期执行短事务，异步模型请求不持有数据库事务。单 worker 不意味着没有异步并发；B 的预算预留须有进程内互斥及原子落盘，版本校验与写入须原子执行。实施时验证线程／事件循环、取消与事务边界，不能仅设置 SQLite 线程选项就宣称并发安全。

保留浏览器本地 DOCX／PDF 解析路线及全部业务约束，不因后端改语言自动迁移解析库；DeepSeek 适配改用 Python 客户端，具体 SDK 版本、图片／工具调用协议须重新验证。Python 以项目 .venv 隔离依赖，前端依赖仍由 npm 管理；两侧分别锁定版本，不通过 npm 安装 Python 依赖。[venv 文档](https://docs.python.org/3.13/library/venv.html)

用户已回复“技术方案通过”，本文的具体栈、默认参数和接口作为后续实施与验证基线；试验性输入限制仍需按样例结果校准，不等于能力已经验证，也不自动授权开发。

### 1.2 运行边界

- 浏览器：界面、本地解析、临时编辑状态、确认操作和导出；业务历史不以浏览器存储为准。
- 本机后端：SQLite 业务数据与原附件、模型密钥、Agent 运行、工具校验、确认写入、调用预算与独立成本账本。
- DeepSeek：接收必要的文本／图片，生成识别结果或行动选择；不能直接连 SQLite 或自行更新正式稿。
- 不引入云端业务数据库、向量数据库、联网搜索、通用代码执行、文件系统读写或 shell 工具。
- 本机服务仅绑定回环地址。固定工作台地址 `http://127.0.0.1:5173`，后端 `127.0.0.1:3001`，前端代理 `/api`；端口占用报错，不自动换端口。换浏览器或清除网站数据不删除 SQLite 历史；同一后端数据库被替换或删除才影响这些记录。不增加登录、远程部署或跨设备同步。

## 2. 模型接入与材料处理

### 2.1 DeepSeek 接入

候选配置：官方地址 `https://api.deepseek.com`，模型 `deepseek-flash`，Chat Completions 接口。官方文档当前列出该模型支持工具调用和图像输入；不使用旧别名，不自动切换更贵模型或第二家服务。[官方接入](https://api-docs.deepseek.com/quick_start/agent_integrations/)、[工具调用](https://api-docs.deepseek.com/guides/tool_calls/)、[图像输入](https://api-docs.deepseek.com/guides/vision/)

密钥只从本机后端环境变量 `DEEPSEEK_API_KEY` 读取，不使用会注入前端包的变量前缀，不写入业务数据库、请求日志、错误正文或下载稿。用户自行在本机配置，无需发送到聊天中。

默认关闭思考模式，先验证普通工具调用；若后续对照试验需要思考模式，再单独说明协议与成本变化。不依赖 Beta strict 功能；所有工具参数和结果均由后端进行结构校验，不将合法 JSON 等同于事实正确。[思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)

### 2.2 输入处理路线

| 输入 | 本地处理 | 模型收到的内容与恢复方式 |
| --- | --- | --- |
| 粘贴／.md | 读取文本，保留行号与原始内容 | 有来源编号的文本；空内容提示补充 |
| .docx | Mammoth 提取段落／表格相关内容并转为文本块；不执行转换生成的 HTML | 文本块及来源；不能完整提取时明确提示，允许粘贴，不宣称任意 Word 版式均可靠 |
| 文字型 PDF | PDF.js 按页获取文字及位置，保留页码 | 按页文本块；可疑错序或内容缺失允许用户修正，必要时请求对应页的视觉读取 |
| 扫描／混合 PDF | PDF.js 按页检查文字层；需要识别的页渲染为图片 | 仅待识别页按需作为图片输入；原 PDF 顺序不变，页间部分失败可局部继续 |
| PNG/JPEG 截图 | 校验实际内容、解码图片、保留原图；按需缩放，保留坐标变换 | 图片及识别任务；保留识别结果，后续普通改写优先复用文本 |

工具依据：[PDF.js 页面与渲染](https://mozilla.github.io/pdf.js/examples/)、[PDF.js 文字提取 API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html)、[Mammoth 项目说明](https://github.com/mwilliamson/mammoth.js)。这些库能提供解析基础，不保证阅读顺序、文本框或复杂排版完整；尤其双栏 PDF 和 Word 浮动对象需要样例验证。

视觉识别使用同一个候选模型，是材料工具内部的一次调用，不额外建立一个自治 Agent。只转录、分类与定位，不在识别步骤润色经历。扫描页识别和截图理解都计入总预算。

截图以本次请求的内联图片发送，不发布公共图片链接；首版不使用 Files API 持久上传。已确认可复用的识别结果按附件内容摘要、页码、处理参数与识别版本缓存。重传相同材料不自动重复识别；用户主动要求重新识别时仍须通过预算检查。

### 2.3 自动分类与排序

解析产生材料清单后，由 Agent 依据内容识别为简历、JD、补充材料或待澄清，显示识别结果供用户纠正。未知角色不默认为个人事实；不能把 JD 要求写入用户经历。

PDF 内部页序由程序锁定。截图顺序由 Agent 结合页码、标题和内容衔接提出，并保留原附件标识；不确定则提问，不能静默删除或拼出不存在的内容。再次上传区分补充、参考新版、整体替换与另一人／岗位；不明确时澄清，不自动合并或覆盖。另一人／岗位引导新会话，明确同人同岗位替换按第 3.4 节执行。

建议验证起始限制：每文件 10 MiB、每会话 10 个附件、PDF 合计 20 页、粘贴与提取正文合计 50,000 字符，视觉一次处理一页／一图；图片最长边处理目标不超过 2,000 px，保留原图。以上用于限制测试规模，不是用户已确认的规格；用真实简历检查清晰度和容量后再定案，调整时同步 PRD。加密 PDF、损坏文件和解码失败明确报错并提供粘贴恢复。

## 3. 数据与依据的可追溯设计

### 3.1 数据对象

| 对象 | 最小字段与作用 |
| --- | --- |
| Session | id、求职方向、当前状态、时间、stateRevision、可选 JD 引用 |
| Attachment | id、sessionId、文件名、实际类型、内容摘要、原文件 BLOB、原始序号、识别状态 |
| SourceBlock | id、sessionId、attachmentId／messageId、材料角色、页码／段落／行号、原文、sourceRevision、识别方式 |
| Message | id、sessionId、角色、正文、时间、是否为用户补充／纠正／跳过 |
| DraftBlock | id、sessionId、Markdown、blockRevision、来源关联、最近写入类型 |
| Suggestion | id、目标块及其旧版本、旧文／新文、操作、理由、sourceRefs、信息缺口、状态 |
| Issue | id、范围、问题类别、优先原因、引用、未解决／已处理／已跳过状态 |
| Run | id、sessionId、generation、输入版本、运行状态、已执行事件与错误类别 |

编号由程序生成，模型只能引用提供给它的编号。`sourceRefs` 指向不可变的来源快照，不只保存一段会变化的摘要。来源校验必须确认引用属于当前会话且确实存在；文字引用必须能对应快照，但这只能验证“来自哪里”，不能证明经历真实或改写在语义上完全忠实。

材料被纠正时创建新来源版本，保留旧版本供解释历史建议。用户直接编辑正式稿标记为 `user_edit`，不把新增文字自动归因于旧材料。无来源的模型推断不能标为已证实个人事实。

### 3.2 初始稿与建议

初始稿依据已识别为简历的来源块组装，保留信息和顺序，仅做必要的 Markdown 格式整理；不在此阶段擅自优化、删减或加入 JD。无法确定格式转换是否改变含义时，作为建议呈现，不写入初始稿。

建议操作限定为替换、插入或删除一个独立块，必要时以独立字段建块；携带 `blockId`、`expectedBlockRevision` 和旧内容。模型提交建议后，后端校验并保存待确认建议，不改正式稿。用户接受时，浏览器发送接受请求；后端重新核对会话、建议状态和目标版本，在一次 SQLite 事务中更新正文、建议状态与来源关联，提交成功后浏览器刷新结果。模型工具不能调用这条用户写入路径。

整稿编辑采用完整 Markdown 编辑器。后端接收 Markdown 与预期版本，保存时按顶层标题／段落／列表项分块并对照旧稿：确定未变的块保留编号；改变、合并、拆分或无法唯一对应的块分配新版本／编号，并在同一数据库事务中使相应旧建议失效。无法安全映射时宁可扩大失效范围，不按相似文字猜测并覆盖。实现需测试重复段落和列表嵌套。

插入位置要引用相邻块及版本。无论重复接受还是连续点击，都不得重复插入。用户拒绝只改建议状态；要求调整创建新建议并关联旧建议，不篡改历史依据。

### 3.3 保存与删除

业务数据库固定在后端项目的 `.local/resume-agent.sqlite`，不提交到 GitHub；应用启动时创建／检查 schema_version 与按序的非破坏性 schema 迁移。当前没有产品实现或旧用户数据，不需要 IndexedDB 数据迁移。SQLite 不是云端数据库，无需单独购买服务器或安装数据库守护进程。

按 Session、Attachment、SourceBlock、Message、DraftBlock、Suggestion、Issue、Run 建立对应表；sourceRefs 使用关联表保存。原附件以 BLOB 同库存储，避免另一个附件目录与数据库删除不一致。所有会话相关查询必须由 Repository 绑定 sessionId，不接受模型生成任意 SQL、表名或文件路径。

每个连接显式启用外键约束；建立会话／来源／时间检索索引、必要的非空／唯一／状态约束。外键及应用校验共同防止无效来源；同一来源只能被当前会话建议引用。事务只包含短时数据库读写，不等待模型、网络或浏览器；提交成功后才显示“已保存”。[SQLite 外键](https://www.sqlite.org/foreignkeys.html)、[事务说明](https://www.sqlite.org/transactional.html)

对话、建议、事件与稿件由后端保存；编辑停顿约 500 ms 后发版本化保存请求，并在切换会话前等待确认。数据库不可写、磁盘不足或后端离线时，保留浏览器可见内容、提示尚未持久化并允许导出，不能依赖关闭页面事件保证保存。后端重启时将遗留运行标记为已中断，重开不自动重发付费请求。

删除整会话时，先使运行代号失效并尽力取消请求，再在事务中删除会话、附件、文本、问答、建议、依据和当前稿。所有迟到响应写入前必须检查会话存在及运行代号，不能重新建立已删除会话。已发出的模型调用可能仍产生费用，本机成本账本不随会话删除。

首版仍按单个操作员使用；多标签或不同浏览器访问同一本机后端时，服务端依照 stateRevision／blockRevision 校验所有写入，旧版本返回冲突而不覆盖最新稿。浏览器内保留单工作台标签提示作为体验辅助，但不将它当成跨浏览器锁。没有账号，能访问同一后端的使用者可查看同一会话列表；同会话逻辑隔离不等于多人身份隔离。

### 3.4 同会话新版替换与来源有效范围

建议扩展 Session.currentResumeGeneration，SourceBlock 的当前用途状态（待澄清／有效／历史）及所属简历代次；消息中的经历补充也须具备有效范围，不能只过滤附件却把旧问答重新塞入模型上下文。与 Run.generation 的运行代号区分。历史引用读取不受当前检索过滤影响，但须标示替换前记录；模型运行只可查询当前有效来源，待澄清与历史来源不作为当前事实。用户明确沿用某条旧补充后才重新启用其事实范围，保留原引用及沿用记录，存在冲突仍澄清。

整体替换是用户业务操作，建议 POST /api/sessions/:id/draft/replacement，输入 requestId、expectedStateRevision、expectedDraftRevision、新简历材料编号及已保存的明确用户要求引用；具体字段在共享类型实现前由 A/B 对齐。Agent 只识别意图、展示影响及提出候选，不能以模型工具直接调用此操作；明确自然语言要求经用户操作路径交给后端，不以“模型说用户同意”代替授权。

先检查材料归属、解析成功与完整性；部分成功或用途不明不能整体替换。形成仅做格式整理的候选 Markdown；保存前检查版本及授权。一个 SQLite 短事务内：记录替换前后正文／材料范围、切换当前稿并使用全新块编号、递增稿件／上下文及当前简历代次、失效全部旧 pending、归档旧问题、调整有效来源与问答范围、使旧运行失效。替换前原件／对话／已决建议保留，JD 与求职方向保留；不自动迁入旧优化或旧经历补充。

提交成功才展示新版并尽力取消旧请求；写入仍须检查代次／版本，迟到结果不能落库。事务失败不改变原稿及旧建议／材料状态，不能先永久失效旧运行再假称状态全部回滚；实际进行过的取消如需恢复，应明确提示重新发起。重复 requestId 返回同一替换结果，不重复递增或调用模型。替换记录只用于追溯，不增加历史稿切换／恢复／对比。具体表结构、意图识别和接口需实施时验证。

## 4. Agent 的循环、工具与停止条件

### 4.1 每轮如何运行

用户点击开始、回答问题或提出新要求后，程序创建本次运行，把目标、当前稿、材料清单、未解决问题、有效建议和最近反馈提供给模型。模型按当前情况决定行动；材料多时通过工具取原文，不把其他会话或全部历史无条件塞入。

一次模型响应可以请求工具，也可以结束本轮等待用户。后端校验工具名、参数、会话范围与预算，执行后将结果与原 `tool_call_id` 成对返回模型，再由模型判断下一步。首次必须给出最多 3 个重要诊断点，但不规定后续必须“先追问再改写”。

示例：发现“项目推进”缺细节 → 查找本会话补充 → 已有具体行动则提交建议；若无则追问；用户说记不清时有限改写或转向其他问题。新回答纠正已接受职责时，主动查找相关表述并标记冲突，再提出待确认纠正。

### 4.2 提供给模型的工具

| 工具 | 输入 → 输出 | 权限边界 |
| --- | --- | --- |
| read_material | 来源编号、页码范围 → 来源块与定位 | 仅当前会话；不接受任意路径或 URL |
| recognize_page | 当前附件／页编号、原因 → 识别文本与来源块 | 只处理已上传材料；命中缓存先复用，新调用经统一预算控制 |
| set_material_interpretation | 材料角色、截图顺序、依据／歧义 → 分类结果或澄清项 | 不能改变 PDF 页序；用户纠正优先 |
| search_evidence | 关键词、可选来源范围 → 匹配原文及编号 | 普通文本检索即可，不新增向量库／RAG；不得跨会话 |
| read_draft | 块编号范围 → 当前块与版本 | 只读最新可用稿，不将待接受建议当正式内容 |
| record_issues | 问题、优先理由、来源、受影响块 → 诊断／冲突记录 | 标记问题，不直接改写正文 |
| propose_change | 操作、目标版本、新文、理由、来源、缺口 → 待确认建议 | 没有正式稿写入权限；不能接受自己的建议 |

问用户、说明进展和给交付总结由结构化回合结果呈现，不为每句话造工具。模型只能使用白名单工具，不能自行触发接受、删除会话、导出文件、提高预算、修改密钥或联网搜索。

### 4.3 程序约束与可见状态

- 建议默认：每次用户触发运行最多 6 次付费模型请求（含视觉），最多 12 次工具执行，每次模型输出上限 4,096 tokens。SDK 自动重试关闭；这些是保护循环的上限，不是固定追问轮数。
- 遇到需要回答、需要用户接受建议、达到上限、预算不足、错误或用户打断时结束本轮；已经完成的诊断和建议仍保留。
- 校验失败时最多允许一次受预算控制的模型修复，仍计入本轮请求上限；不能因为格式错误无限循环。用户拒绝不是错误，不自动反复生成相同建议。
- 状态为 idle、running、waiting_user、interrupted、failed、budget_blocked；状态管理由程序执行，不让模型宣称某项写入已完成。
- 相同内容反复调用工具且无新增结果时停止并解释卡点。达上限不代表任务完成，用户可明确选择继续。
- 已发送的调用取消后不保证不计费；不能在 Abort 后自动退回预算预留。

## 5. 前后端接口与失效控制

以下为 SQLite 调整后的建议契约，不是现有接口。后端是业务数据的唯一持久来源，前端通过接口读取、编辑和确认，不再把会话快照或数据库内容当作由浏览器权威提交的数据。

| 接口 | 请求与返回 | 责任 |
| --- | --- | --- |
| GET /api/health | 配置是否就绪、候选模型、价格快照时间 | 只报告状态，不返回密钥，不自动调用付费模型 |
| GET /api/budget | 已记录费用、未知费用预留、可用预算及是否阻断 | 返回本项目账本，不冒充服务商最终账单 |
| GET/POST /api/sessions；GET/DELETE /api/sessions/:id | 列表／创建／恢复／整会话删除 | 由数据库读取，删除联动会话关联记录，不影响独立预算账本 |
| POST /api/sessions/:id/messages | 用户消息、requestId、预期版本 → 已保存消息及新版本 | 保存后作为 Agent 新输入；错误不声称消息已持久化 |
| POST /api/sessions/:id/materials；GET /api/sessions/:id/materials/:materialId | 文本或原附件及解析块 → 已保存材料；按编号取文本或原附件 | 限制文件实际类型与大小，原附件按二进制传输；后端校验归属、解析输出和来源版本，不接受任意磁盘路径 |
| PUT /api/sessions/:id/draft | Markdown、预期版本 → 新稿与失效建议 | 事务更新稿件与建议状态，版本冲突不覆盖 |
| POST /api/sessions/:id/suggestions/:suggestionId/decision | accept/reject/revise、预期块版本、操作标识 → 状态及最新稿 | 仅用户操作路径可接受；重复操作幂等，事务提交后回显 |
| POST /api/agent/runs | requestId、sessionId、预期版本、触发事件 → 运行事件流 | 从 SQLite 装配当前会话的上下文，校验与去重，不接受客户端自造整份来源快照 |
| POST /api/agent/runs/:id/cancel | 当前运行代号 → 尽力取消结果 | 取消后客户端不再应用该代号的结果 |

运行事件通过 fetch 流返回，事件包含 sessionId、runId、generation、序号、类型和必要数据。类型限定为进度、工具进度、诊断、问题、建议、冲突、结束、错误。后端校验后持久化完整事件，再向浏览器发送；客户端不把尚未收全的 JSON 或流式文字当可接受建议。重开按数据库已提交状态恢复。

read_material／search_evidence 通过 Repository 查询运行绑定会话的来源，视觉工具从已保存附件按页读取；不再需要浏览器工具读取回传或 /tool-result 接口。PDF 渲染和 Word 提取仍可在浏览器本地完成，经上传接口保存原件与提取结果；模型调用前材料必须已成功保存。模型只提出参数，由 Host 限定会话与来源，不能请求通用 SQL。

统一错误类别：invalid_input、parse_failed、ambiguous_material、stale_state、invalid_tool、invalid_model_output、provider_error、budget_exceeded、storage_failed、cancelled。错误返回可执行的恢复动作，不暴露密钥或原文堆栈。

同一会话只允许一个运行；用户编辑、纠正、接受建议时取消旧运行并增加 stateRevision。工具执行及事件应用检查 sessionId、generation 和预期版本：不一致就丢弃旧事件。切换会话默认取消当前运行，成功持久化的内容仍保留；服务端保留有时限的请求去重记录，防断线重连导致重复付费。

仅接受本机工作台 Origin；拒绝跨站请求，使用启动时生成的本地请求令牌保护产生费用的接口。该令牌不是账号功能，不写入用户历史。模型请求目标固定为配置的服务地址，材料中的 URL 不能转为服务器请求。

## 6. 30 元预算与费用账本

### 6.1 费率依据与保守预留

2026-10-19 官方中文价格页列出 Flash 高峰未命中输入 2 元／百万 tokens、输出 8 元／百万 tokens。以较高费率估算，不把缓存或空闲折扣当成必定发生。[官方价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

建议每次付费请求先预留 3 元。此数不是预计单次费用，而是按当前公布的约 1M 上下文规模、上述较高输入价格及 4,096 输出上限留出的保守保护额。实施前必须重新核实上下文、图片计量、实际账号币种及费率；无法成立则不启用付费调用。不能在别名、计费或输出上限改变后继续沿用旧预留。

成功后根据返回 usage，按较高未缓存输入与输出费率记账，释放多余预留；缓存和折扣不必用于扩大预算。无 usage、超时、连接中断、取消等无法确认费用的调用保留整笔预留，不推定为零；先核账再释放。预留不足以容纳下一次调用时提前停止，即使最终真实费用可能很低。

### 6.2 账本独立保存

- 本机后端在项目忽略目录 `.local/` 保存不含简历内容和密钥的成本账本：请求编号、模型、费率快照、预留、usage、已记费用、未知状态与时间；不在本轮创建该目录或实际账本。
- 金额采用人民币微元整数运算，所有费用上取整；总额 30,000,000 微元。将“已计费用＋未结预留＋下一请求预留”与总额比较。
- 单进程串行进行费用预留并原子落盘；账本写入失败不得调用模型。仅允许一个后端实例；请求重试也必须重新预留，不能共享已用的预留。
- 后端重启后未结预留继续占用；新建、删除会话或清空浏览器不清零账本。历史接入测试若已消费，需要在本轮起始余额核对中计入。
- 首次试用记录服务商余额基线，试用后核对；余额接口是账户总额，其他应用消费、充值或赠金到期都可能干扰差值，不能当作本项目精确流水。[余额接口](https://api-docs.deepseek.com/api/get-user-balance/)
- 未配置模型、费率或有效账本时停止付费入口。本应用只能约束经本机服务发起的调用，不能限制该账号在其他工具中的支出，也不能把估算账本宣称为服务商账单。

预算阻断时原附件回看、手动编辑、复制与 Markdown 下载仍可用。增加预算必须由发起者另行明确决定，Agent 无此工具权限。

## 7. 验证顺序、风险与评审

### 7.1 先验证什么

1. 不付费先验证本地文件解析和来源定位：MD、DOCX、文字 PDF、双栏 PDF、图片与扫描页渲染；检查漏字、错序、表格与浮动对象。
2. 以模拟模型响应验证工具白名单、来源校验、逐条接受、重复操作、直接编辑失效、取消后迟到响应、删除与本地恢复、预算预留；先证明权限由程序控制。
3. 配置由用户保管的密钥后，在总预算内验证一条普通工具调用和一张构造／脱敏图片，不先做大批量调用；记录模型、参数、实际 usage、费用与输出。
4. 用同一段经历的三种情境检验自主性：已有足够依据、缺少关键行动、用户不愿补充；观察是否分别选择直接建议、关键追问和有限改写／转向。
5. 对照 PRD 的 23 项用例记录实际结果；技术测试新增请求去重、版本冲突、账本重启和本地标签协同。独立测试与评估方案另行细化。

### 7.2 未验证风险

| 风险 | 处理与不作的承诺 |
| --- | --- |
| 模型图片缩放可能影响小字和数字识别 | 用实际截图测试，可按页／区域重读；不能以低分辨率省钱后声称内容完整 |
| DOCX 浮动对象、PDF 阅读顺序不可靠 | 保留原件和定位，异常提示修正／粘贴；不能静默删掉无法提取的经历 |
| 来源引用正确但改写仍夸大 | 程序只验证可定位与权限，语义需规则、样例评估和用户确认共同约束 |
| 数据库不可写、磁盘不足或后端不可用 | 明示保存失败、提供可用正文导出；浏览器清理不删除后端记录，数据库文件丢失也不自动恢复 |
| 预算估计与真实计费差异 | 先预留、关闭自动重试、未知费用不释放、核实费率和余额；不冒充账户级硬限额 |
| 不同岗位诊断水平不一 | 标明限制，按试过的岗位记录效果，不将目标范围当成验证范围 |
