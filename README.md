# 历历在练

面向实习求职场景的简历修改 Agent。用户提供简历、求职方向及可选岗位描述后，通过对话说明需要调整的内容；Agent 基于材料追问、提出有依据的改写，经用户明确确认后更新当前稿，支持预览、复制与 Markdown 下载。

本文按 2026-10-24 当前工作区代码整理。真实文本模型已接入并完成本机样例联调；启用 `VISION_ENABLED=1` 后 PNG／JPEG 上传会调用 `deepseek-flash` 转录文字，扫描型 PDF 仍只预览。样例跑通不等于所有岗位、文档格式或改写质量已经验证。

## 当前功能

| 功能 | 当前状态 |
|---|---|
| 对话式交互 | `/` 首页直接进入新版聊天，原 `/chat` 链接继续有效；支持创建、重开会话及恢复已保存消息与附件 |
| 文字简历 | 支持直接粘贴到聊天；无稿件历史时识别候选文字，确认用途后原样建立初始稿并分析 |
| 文档与图片 | 支持 Markdown、DOCX、PDF、PNG／JPEG；DOCX／文字型 PDF 可提取文字，PNG／JPEG 可选用 `deepseek-flash` 转录，扫描页仍只本地预览 |
| 真实文本分析 | 满足配置与预算条件后，接入 B 的 Agent 循环与模型调用，支持追问和提出改写 |
| 建议确认与依据 | 接受、拒绝或要求调整；检查目标、来源版本及用户答复范围，明确接受后才更新当前稿 |
| 当前稿 | 自动保存、版本冲突处理、编辑、安全预览、复制及 Markdown 下载 |
| 失败与恢复 | 保存失败保留输入；分析按已保存消息启动，支持停止、请求重放及迟到结果保护 |
| 历史兼容 | 旧会话继续恢复；模拟历史明确标记并只读回顾，不自动转为个人事实 |

自动分类每份材料最多读取 12000 字符；超出、未完整提取或多份简历无法确定用途时保留附件并询问，不截取后当完整简历导入。整体替换支持 Markdown，以及完整提取且无警告的 DOCX／文字型 PDF；图片转录结果暂不作为整体替换候选。

原始消息、待确认材料、改写建议与当前稿分别保存。上传成功不代表已识别，文字可读不代表用途已确认，生成建议也不等于已经修改正文。

## 技术结构

- 前端：TypeScript、React、Vite。
- 后端：Python、FastAPI、Uvicorn；业务接口与 Agent 在同一个后端服务中运行。
- 数据：SQLite 保存会话、原件、来源快照、稿件、建议、运行事件及项目费用记录。
- 模型：当前客户端默认使用 DeepSeek 文本模型；浏览器不持有模型密钥。
- 文档处理：DOCX／文字型 PDF 本地提取，PDF／图片本地转图与预览；PNG／JPEG 在聊天处理中可调用 `deepseek-flash` 转录（`VISION_ENABLED=1`，且确认项目预算），扫描型 PDF 未接入识别。

```text
frontend/src/
  ChatPage.tsx          对话、附件与当前稿界面
  chatSend.ts           消息与附件保存、重试
  chatAgent.ts          已保存消息的分析请求与事件接收

backend/app/
  main.py              应用装配、初始化与健康检查
  api.py               用户业务 HTTP 接口
  business_service.py  业务事务与请求去重
  repository.py        会话数据、来源与版本校验
  agent_host.py        聊天与 Agent 的受信协调入口
  agent_text_intake.py 聊天文字的用途确认与首次导入
  agent/               B 的路由、循环、工具、记忆和模型客户端
  agent_budget.py      项目费用账本与预留结算
  migrations/          追加式数据库迁移

backend/tests/         后端隔离检查
frontend/tests/        前端请求、保存与恢复检查
```

## 本机启动

使用 Node.js 24、Python 3.13，依赖以 `frontend/package-lock.json` 与 `backend/requirements.txt` 为准。前后端分别在两个 PowerShell 终端运行。

### 1. 基础后端：先检查保存与预览

首次准备环境，在项目根目录执行：

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

已有环境时直接在 `backend` 目录启动。以下模式关闭真实分析，不要求模型密钥：

```powershell
$env:AGENT_ENABLED = "0"
$env:AGENT_BUDGET_CONFIRMED = "0"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 3001 --workers 1
```

### 2. 前端

另开终端，从项目根目录执行：

```powershell
cd frontend
npm ci
npm run dev
```

打开 [项目首页](http://127.0.0.1:5173/)，直接使用新版聊天界面。原 [聊天链接](http://127.0.0.1:5173/chat) 和其中的 session 查询参数继续有效。旧工作台与纯内存视觉示例已删除，前端只加载同一个真实聊天页面。

前端固定监听 `127.0.0.1:5173`，把 `/api` 代理到 `127.0.0.1:3001`；端口被占用时不会自动换端口。停止对应服务可在其终端按 Ctrl+C。修改后端代码或配置后，需要重启实际进程才能生效。

### 3. 可选：启用真实文本分析

先核对历史模型费用与统一账本，再停止原后端，选择一种方式启动。基础保存、预览和导出不要求开启真实模型。

**方式一：设置当前 PowerShell 的进程环境。** 在 `backend` 目录执行，密钥通过隐藏输入读取，不写入命令历史中的明文参数：

```powershell
$env:DEEPSEEK_API_KEY = [System.Net.NetworkCredential]::new("", (Read-Host "输入模型 API Key" -AsSecureString)).Password
$env:AGENT_ENABLED = "1"
$env:AGENT_BUDGET_CONFIRMED = "1"
$env:AGENT_PROJECT_LIMIT_CENTS = "3000"
$env:VISION_ENABLED = "1"
$env:VISION_MODEL = "deepseek-flash"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 3001 --workers 1
```

图片识别由聊天 Host 执行，需要同时启用 `AGENT_ENABLED=1`、`AGENT_BUDGET_CONFIRMED=1` 和 `VISION_ENABLED=1` 并配置密钥。视觉转录与文本调用写入同一项目费用账本；单独上传图片只保存原件，不产生识别调用。

**方式二：使用本机已有的配置启动器。** 当前电脑的 `.local/start-backend.py` 会读取 `backend/.env` 中允许的配置，再启动相同后端。从项目根目录执行：

```powershell
.\backend\.venv\Scripts\python.exe .\.local\start-backend.py
```

这个启动器和真实 `.env` 都仅本地保留，拉取 GitHub 代码不会自动获得它们。普通 Uvicorn 命令只读取进程环境，复制 [配置样例](backend/.env.example) 为 `.env` 不会自动加载，也不会自动开启模型功能。

| 配置 | 作用 |
|---|---|
| `DEEPSEEK_API_KEY` | 后端模型凭证；真实值仅本地保存 |
| `AGENT_ENABLED=1` | 允许真实分析入口 |
| `AGENT_BUDGET_CONFIRMED=1` | 表示使用者已核对历史费用与项目账本 |
| `AGENT_PROJECT_LIMIT_CENTS` | 本机统一项目账本上限，单位分，最大 3000；不按会话或日期重置 |
| `VISION_ENABLED=1` | 允许聊天 Host 识别已保存的 PNG／JPEG；须同时确认项目预算 |
| `VISION_MODEL` | 视觉模型 ID，当前预算费率仅支持 `deepseek-flash` |

开启后，模型处理所需的文字会发送至配置的模型提供商并可能产生费用；启用图片识别时，还会发送所需图片。文字与图片共用全项目 30 元预算，图片按每次尝试预留，失败或费用未知时保守计入，不因重启清零；原件与会话记录仍保存于本机。账本不能自动统计其他机器或绕过统一入口的调用，删除会话或新建数据库也不应被当成重新获得项目额度。

## 使用流程

1. 打开聊天页，说明求职方向，粘贴简历或添加附件。岗位描述可选。
2. 可读附件先按正文自动区分简历、岗位描述与补充材料；内容或用途不明确时才询问。已有稿件时，明确要求用完整新版替换即可执行；仅上传另一份简历则先询问替换还是参考。仅供参考的他人简历不作为个人事实。聊天粘贴简历先定位正文起止行并确认用途；原始消息完整保留，范围外的指令不导入当前稿。
3. 只有一份有效 JD 时，默认按该 JD 确定目标并把岗位正文传入分析，不再重复问岗位；没有 JD 或目标不清时才询问。已明确提供的目标不会被自动覆盖。回答必要的经历追问，Agent 依据个人材料与岗位要求提出建议。
4. 对唯一一条当前有效建议且答复对象唯一时，回复“是”“是的”“可以”等简短肯定词即可直接采用，无需再让模型猜测；多条候选、条件或引用表达仍需澄清，过期与范围校验保留。只有确认事务成功后，界面才会反馈当前稿已更新。
5. 在右侧查看、编辑或预览当前稿，再复制或下载 Markdown。

消息已保存与分析已完成是不同状态。分析中断后原话仍可恢复；相同已保存回合的请求重放只返回既有处理记录，需要继续分析时发送新的用户回合。尚未发送的输入与待上传文件不保证在强制刷新或关闭后恢复。

## 文件与功能边界

- Markdown、DOCX、文字型 PDF 可作为文字材料；提取结果可能部分成功或存在遗漏，支持查看与修正原文。
- PNG／JPEG 可以保存、下载与预览；设置 `VISION_ENABLED=1`、确认项目预算并配置密钥后，先保存原件，再由聊天 Host 使用统一项目账本预留并调用 `deepseek-flash` 转录，取得文字后自动分类。已保存的待识别图片可发送“识别图片”继续处理，不必重传；同一处理请求重放复用已保存结果。每轮最多处理 2 张，失败需明确发送“重试识别图片”才再次调用。识别失败或关闭开关时只保存与预览，需粘贴文字或上传文字型文件。扫描型 PDF 仍只有预览，逐页识别未接入。
- 聊天文字的首次接入检查最近 6 条当前简历代次用户消息，单条上限为 20000 字符；正文起止须匹配唯一完整原文行，含糊或正文中夹指令时先要求分开发送。按明确栏目／项目边界无损分段，不通过模型重写导入正文。较长内容优先以文件上传，不截断导入。
- `.doc` 需另存为 `.docx`。损坏、加密、超限或不可读取的材料会返回提示，不静默当作完整解析成功。
- 明确指定项目序号（如“只优化第二个项目”）或可唯一匹配的完整项目名时，后端限制建议及接受操作的目标，并核对简历引用属于该项目的原文范围。后续明确切换项目可更新范围；无法定位或历史整稿未分段时先澄清，不静默重排旧稿。
- 交付格式为 Markdown，不包含 Word／PDF 导出、原版式还原或模拟面试。
- 当前为本机开发运行方式；未提供公网部署、账号系统或真实用户效果验证。
- 事实检查仍有已知边界：离线构造案例中，新增数字／主导职责的来源混用已修复，但凭空新增资格证等一般语义仍可能漏检；引用能打开不代表整句话已获事实支持，不能视为内容质量全面验收通过。

## 数据保存与迁移

默认业务文件为 `backend/.local/resume-agent.sqlite`，按源码位置确定。后端启动时自动初始化或核对结构；当前为 **schema 12／31 表**。迁移保留原件、旧来源与正文快照，未知结构或损坏库明确失败，不删除重建。升级已有库前应保留备份。

在 `backend` 目录可手动执行：

```powershell
# 首次建立或升级结构；再次执行保留数据
.\.venv\Scripts\python.exe -m app.db init

# 只读检查，不创建缺失文件或自动修复
.\.venv\Scripts\python.exe -m app.db check
```

| 数据类别 | 主要内容 |
|---|---|
| 会话与材料 | 消息、附件原件、图页缓存、提取／识别结果 |
| 来源与稿件 | 不可变来源版本、当前及历史正文、确切引用 |
| 建议与决定 | 改写建议、用户答复关联、决定消费与事务结果 |
| Agent 运行 | 运行代次、分析请求、持久事件与上下文记忆 |
| 项目费用 | 调用预留、已结算及未知费用，独立于会话删除保留 |

同会话的引用与写入受范围、版本和有效来源校验；数据库只能保证结构与关联，不能证明用户经历真实或模型表达忠实。工具权限和写稿规则以代码及 [API 说明](backend/API.md) 为准。
